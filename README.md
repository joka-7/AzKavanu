# Az Kavanu · אז קבענו

Study tracking and scheduling with no backend: your data lives in your own Google Drive, and the app works offline.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the design.

## Status

Implemented (architecture phases 1a and 1b):

- Study tracks from a catalogue or your own:
  - about 20 established cycles (Daf Yomi, Mishna Yomi, Daf Yomi B'Halacha, Kitzur, Rambam, Nach Yomi, 929, Tehillim, Tanya and more) and the weekly parasha
  - Talmud daf by daf or Mishnah one by one at your own pace, from any tractate
  - numbered units (chapters, simanim, lessons) or plain counted sessions for anything else: a language, exam preparation, a book, a discussion
- Flexible timing: every day, chosen weekdays, chosen days of the month, or a number of times per week or month on whichever days you choose. Own-pace tracks advance only when a session is marked done.
- Calendar in Hebrew or Gregorian months with per-day check-off, holidays and streaks; schedules can use days of the Hebrew month
- Daily links: built-in Sefaria links for the fixed cycles, URL templates for everything else
- Local-first storage in IndexedDB, installable as a PWA, English and Hebrew (RTL)
- Google Drive sync into the hidden app-data folder, with per-record merge between devices
- Every day's study has a Done button, an add-or-change link control (for when no link is found or you prefer your own page) and a quick reminder
- Direct links into the author's own study apps: Talmud days (Daf Yomi, Amud Yomi, Daf Weekly, own-pace Talmud) open the page in Shas Radar; Nach Yomi, 929, Tanakh Yomi, Tehillim and the weekly parasha open the chapter in אות ואות. The two addresses are set in `packages/core/src/apps.ts`.
- Add a study to your own calendar with details, a repeat rule (the track's own schedule, daily, weekly, monthly; ends never, on a date or after N times) and an alert, either as one repeating event (Google Calendar link or calendar file) or as a separate event per day carrying that day's study and link
- Reminders: while the app is open, or as a downloadable calendar file that fires with the app closed on any phone or computer (the Android app schedules them itself)
- Study groups on any track: one shared Drive file per group, invitations by email, an optional description and maximum size, a seven-day view of each member's progress

- Android app (Capacitor shell): the same interface, with reminders that fire while the app is closed. It is local-only for now, because Google sign-in needs a native implementation on Android.

Not yet implemented: Drive sync and groups on Android, the Google Calendar reminder mirror, signed group sections, the desktop shell.

## Layout

| Path | Contents |
|---|---|
| `packages/core` | Platform-free TypeScript: data model, schedule engine, link resolver, merge, sync engine, reminder planner |
| `apps/web` | React PWA and the browser adapters (IndexedDB, Google sign-in, Drive, notifications) |
| `apps/web/android` | Android project generated by Capacitor; wraps the web build |

## Running

```sh
npm install
npm run dev        # web app at http://localhost:5173
npm test           # core unit tests
npm run typecheck
npm run build      # static site in apps/web/dist
```

## Getting a build without a development machine

Every push runs the **Build** workflow on GitHub Actions. Open the run under the repository's *Actions* tab and download:

- `kavanu-debug-apk`: an installable debug APK (allow installing from unknown sources on the phone)
- `kavanu-web`: the static web build

The **Deploy web to GitHub Pages** workflow publishes the web app on every push to `main`, once *Settings → Pages → Source* is set to *GitHub Actions*. Google settings are read from repository variables named like the `.env` entries below.

To build the APK locally (needs JDK 21 and the Android SDK):

```sh
npm run build
cd apps/web && npx cap sync android
cd android && ./gradlew assembleDebug
```

## Enabling Google Drive sync

Without configuration the app runs in local-only mode. To enable sync:

1. In Google Cloud Console, create a project and enable the **Google Drive API**.
2. Configure the OAuth consent screen with the scopes `https://www.googleapis.com/auth/drive.appdata` and `https://www.googleapis.com/auth/drive.file`.
3. Create an OAuth client ID of type **Web application** and add your origins (for example `http://localhost:5173`) under *Authorized JavaScript origins*.
4. Copy `apps/web/.env.example` to `apps/web/.env.local` and set `VITE_GOOGLE_CLIENT_ID`.

Joining a group that someone else created also needs the Google Picker, so that the user can grant the app access to that one shared file:

5. Enable the **Google Picker API**, create an API key restricted to it, and set `VITE_GOOGLE_API_KEY` and `VITE_GOOGLE_APP_ID` (the Cloud project number).

The sync and group logic is covered by unit tests and by a browser test against a simulated Drive API; none of it has yet been run against a real Google account, and the Picker step of joining a group is not exercised by any test.
